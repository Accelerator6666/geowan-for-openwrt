# GeoWAN v0.6.1 — Alert-only Detection

## Purpose

Add a conservative, local alert-only stage on top of the v0.6.0 Sensitive Port Guard. This release turns sampled access observations into reviewable clues without changing any firewall verdict.

## Initial rule

- Rule ID: multi_port_access
- Default window: 10 minutes
- Default threshold: one source IP observed on at least 3 distinct public destination ports and at least 3 sampled events
- Cooldown: 15 minutes per source and rule
- Retention: 30 days, capped at 50,000 alert records
- Severity: notice; this is an investigation clue, not a confirmed attack

The rule only considers events associated with currently active, non-conflicting service mappings. It does not use country, city, ASN, ISP, or network ownership as a maliciousness signal.

## Data and presentation

- Store alert records in a separate guard_alerts SQLite table.
- Keep the original guard_events table and v0.5.x events table unchanged.
- Join GeoIP fields at read time from the existing local geoip_cache.
- Expose alerts through the existing read-only guard_overview RPC response.
- Display recent alert clues in the existing LuCI Guard panel.
- Allow local threshold overrides through /etc/geowan-console/guard-alert-policy.json. If the file is absent, built-in defaults apply. A malformed policy disables alert evaluation.

## Safety boundary

- No nftables commands are issued by the alert engine.
- No ACCEPT, DROP, REJECT, mark, set, chain, DNAT, routing, or port-forward changes.
- No automatic source block, service block, or GeoWAN blacklist mutation.
- The rule is based on rate-limited kernel log samples. Sample counts are not complete connection counts and may undercount activity.
- A source accessing several published services may be legitimate. Alerts require operator review and do not prove malicious intent.
- GeoIP data is contextual registration/geolocation metadata only; city-level data is approximate.

## Acceptance

1. Three distinct active public ports from one source inside the configured window create one alert.
2. Two distinct public ports do not create an alert under defaults.
3. Repeated observations update the existing alert without exceeding the cooldown.
4. A new alert cycle is counted only after the cooldown expires and the condition is observed again.
5. Disabled or degraded Guard runtime produces no alerts.
6. The LuCI Guard panel displays source, GeoIP, ASN, public ports, sample count and alert-cycle count.
7. Existing Guard observation rules, DNAT mappings, GeoWAN blacklists and v0.5.x analytics remain unchanged.
