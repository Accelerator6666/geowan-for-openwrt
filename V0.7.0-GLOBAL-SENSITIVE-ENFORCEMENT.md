# GeoWAN v0.7.0 — Global Sensitive-Port Enforcement

## Objective

Protect WAN-facing services independently of GeoIP country classification and independently of whether a packet traverses DNAT. A single new connection attempt to a configured sensitive service immediately inserts the public source address into a dedicated IPv4/IPv6 nftables timeout set and drops that packet. The source is then blocked on all WAN INPUT and FORWARD traffic for seven days by default.

Country, city, ASN and ISP are descriptive metadata only. Domestic source IPs receive no exemption.

## Decision model

- Match WAN ingress in both input and forward hooks.
- Match the conntrack original destination port (ct original proto-dst), so a DNAT flow is matched by its public port and a non-DNAT flow is matched by its original destination port.
- Do not require ct status dnat; this is essential for router-local INPUT services and directly routed IPv6 hosts.
- Cover IPv4 and IPv6, TCP and UDP.
- Every active WAN DNAT mapping is protected by default, except explicit RDP/SSLVPN exceptions.
- A configurable static sensitive-port list protects common non-DNAT services, including Synology, SSH/SMB, HTTP/HTTPS admin endpoints, Emby/Jellyfin, Home Assistant, MinIO, databases, Docker, Proxmox and monitoring services. Additional custom non-NAT ports can be added locally.
- RDP defaults: public TCP/UDP 58964 is the default exception. Active redirects targeting backend 3389 are auto-detected and their public port is exempted. Direct WAN TCP/UDP 3389 is not exempt by default and remains a protected sensitive port. Generic WAN ACCEPT rules do not create a direct-RDP exception; only active RDP DNAT mappings or explicit local exception entries do.
- SSLVPN defaults: TCP/UDP 20443 is an exception. Active WAN redirects and WAN ACCEPT rules named SSLVPN are auto-detected; other custom SSLVPN ports must be added to local exception_ports.
- JumpServer is not an automatic exception; its active WAN mapping is protected unless explicitly configured otherwise.

## Global source ban semantics and exceptions

After a source hits any protected port once:
- Add its source IP to geo_guard_ban4 or geo_guard_ban6 in the nftables packet path.
- Drop the triggering packet immediately.
- Drop subsequent WAN INPUT and FORWARD traffic from that source, regardless of destination port or application protocol.
- Preserve RDP/SSLVPN access by exempting their configured destination-port tuples from both trigger rules and Guard's global ban-drop rules. This is a Guard exception only; existing GeoWAN country rules and other firewall policy still apply.
- Default ban TTL is 604800 seconds (7 days). The TTL is not extended by later packets; a new hit after expiry can create a new ban.

## Persistence and recovery

- Kernel dynamic timeout sets are authoritative for immediate enforcement.
- SQLite guard_bans and guard_block_events persist trigger evidence and absolute expiry.
- The monitor reads the first-hit kernel log at five-second cadence and writes it to SQLite.
- The five-minute reconciliation and startup restore path recreate missing Guard sets/chains after fw4 reload/reboot and restore non-expired bans.
- Existing geo_black4/6 sets and country-filter policy are not reused or modified.

## Safety and rollout

- Initial installed mode is observe: INPUT/FORWARD rules only log protected-port attempts; no source set is created and no verdict is changed.
- Enforce must not be enabled until the router preflight confirms the detected RDP and SSLVPN exception ports, protected redirect inventory, and nft syntax.
- The installer does not reload firewall or change existing DNAT, GeoWAN country rules, routing, VPN, RDP or listeners.
- Conflicting public DNAT mappings remain protected by their public address-family/protocol/port tuple; backend-dependent automatic exception detection is skipped until the conflict is resolved.
- Existing Guard observation chain and v0.6 alert analytics remain independent.
- If UCI, nftables inventory, WAN device or ownership signatures cannot be validated, the updater leaves currently installed enforcement chains untouched and reports degraded state.
- Uninstall removes only chains and sets carrying the exact v0.7 ownership comments.

## Acceptance tests

1. Domestic and foreign IPv4/IPv6 sources are treated identically by the enforcement rules.
2. A single TCP or UDP NEW packet to any protected port inserts the source address into the family-specific timeout set and drops it.
3. INPUT and FORWARD paths are both covered.
4. DNAT and non-DNAT flows are both matched using the original destination port.
5. RDP and SSLVPN ports do not trigger bans and remain exempt from Guard's global ban drop.
6. A source banned by any other protected port is blocked on unrelated WAN ports.
7. A non-expired ban is restored after a fw4 reload/reboot.
8. Existing GeoWAN country sets, GeoWAN rules, DNAT mappings and RDP/SSLVPN service configuration are unchanged.
9. Observe mode produces no DROP/REJECT/ACCEPT verdict statements.
